# Barbellog: архитектура фронтенда

## Стек и запуск

Клиент находится в `frontend/barbellog-frontend`: React 19, TypeScript, Vite и React Compiler. Приложение — один клиентский SPA без отдельной библиотеки маршрутизации и без выделенного глобального state manager. Корневая команда `npm run dev` поднимает фронтенд и API; отдельно клиент запускается командой `npm run dev` в его каталоге. В dev-режиме Vite слушает `http://localhost:5173` (не выбирает запасной порт) и проксирует `/api` на `http://localhost:3000`.

## Структура и точки входа

- `src/main.tsx` создаёт React root и монтирует `App` в `#root`.
- `src/App.tsx` содержит клиентскую навигацию, экраны, локальное состояние и UI-сценарии. Это крупный файл; при изменении поведения сначала найди нужный экран и его вызовы `api()`.
- `src/api.ts` содержит базовый URL API, типы DTO, хранение сессии и общий HTTP-клиент.
- `src/index.css` и `src/App.css` содержат глобальные и прикладные стили.
- `src/assets/` содержит изображения интерфейса; `public/` — статические файлы.

## Навигация и экраны

`useRoute()` в `App.tsx` хранит текущий `window.location.pathname`, меняет URL через `history.pushState` и синхронизируется с `popstate`. Это простая клиентская маршрутизация: новые пути нужно согласованно добавить в разбор пути, экран и навигацию. Отдельного route table или серверного API маршрутизатора здесь нет.

| Путь или шаблон | Экран | Основное поведение |
| --- | --- | --- |
| `/` | Landing | Публичная стартовая страница; переход к входу, регистрации или дневнику |
| `/login`, `/register` | AuthPage | Вход и регистрация; получение `Session` из API |
| `/app` | DiaryPage | Список тренировок с фильтром периода |
| `/app/workouts/new` | WorkoutEditor | Создание тренировки |
| `/app/workouts/:id` | WorkoutEditor | Загрузка, изменение и удаление тренировки |
| `/app/exercises` | ExercisesPage | Поиск и фильтрация упражнений, создание/изменение личного упражнения, архивирование |
| `/app/exercises/:id` | ExerciseDetail | Детали упражнения и его статистика |
| `/app/stats` | StatsPage | Сводные повторы и объём по группам мышц и неделям |
| `/app/profile` | ProfilePage | Отображение текущего пользователя и выход |

`AppShell` выбирает экран по строковым проверкам пути. Любой путь с `/app` требует локальную сессию; при её отсутствии выполняется переход к `/login`. Незнакомые пути не показывают отдельную 404-страницу — попадают в основной экран приложения или лендинг в зависимости от префикса.

## Состояние и сессия

Состояние экранов хранится локально в React `useState`, а загрузка данных выполняется в `useEffect`/обработчиках событий. Общего кэша запросов или слоя нормализованного серверного состояния нет. При асинхронных эффектах, где это важно, используется флаг `active`, чтобы не обновлять состояние после размонтирования.

`src/api.ts` управляет сессией:

- Ключ `barbellog.session` хранит сериализованный объект `{ token, user }` в `localStorage`.
- `getSession()` возвращает `null` при отсутствии или ошибке разбора значения.
- `saveSession()` записывает объект; `clearSession()` удаляет его.
- При старте `App` вызывает `/auth/me`; при любой ошибке проверки очищает сессию и показывает публичное состояние.
- Выход очищает локальное значение. Серверного endpoint-а отзыва токена в текущей реализации нет; токен сам истекает через семь дней.

## HTTP-клиент и контракты

`API_BASE` равен `import.meta.env.VITE_API_BASE_URL || '/api/v1'`. Общая функция `api<T>()`:

1. читает сессию и добавляет `Authorization: Bearer ...`, если токен есть;
2. по умолчанию отправляет `Content-Type: application/json`;
3. преобразует успешную оболочку `{ data }` в значение типа `T`;
4. возвращает `undefined` для `204`;
5. при ошибке ответа или некорректном JSON выбрасывает `ApiError` со статусом и сообщением.

`query()` формирует URL query string и пропускает пустые/undefined значения. Типы `User`, `Exercise`, `Workout`, `ExerciseStats` и `MuscleStats` в этом файле — клиентские описания ответа API, не runtime-валидация. При изменении DTO нужно сверять фронтенд с серверной сериализацией и [справочником API](../backend/barbellog-backend/API.md).

## Потоки экранов к API

| Сценарий | Клиентские компоненты | Основные запросы |
| --- | --- | --- |
| Вход и регистрация | `AuthPage`, `App` | `POST /auth/login`, `POST /auth/register`, `GET /auth/me` |
| Дневник | `DiaryPage`, `WorkoutCard` | `GET /workouts?from=...` |
| Создание и изменение тренировки | `WorkoutEditor` | `GET /exercises`, `GET /workouts/:id`, `POST /workouts`, `PUT /workouts/:id`, `DELETE /workouts/:id` |
| Каталог упражнений | `ExercisesPage`, `ExerciseDialog` | `GET /exercises`, `GET /catalog/muscle-groups`, `GET /catalog/equipment`, `POST/PATCH/DELETE /exercises/:id` |
| Статистика упражнения | `ExerciseDetail` | `GET /exercises/:id`, `GET /exercises/:id/stats` |
| Сводная статистика | `StatsPage` | `GET /stats/muscle-groups` |

Фронтенд показывает состояния загрузки и ошибок на экранах. Бизнес-валидация и контроль доступа должны оставаться на сервере: клиентская форма не является границей безопасности.

## Существенные детали текущей реализации

- Даты отображаются в русской локали; значения календарной даты формируются в локальном часовом поясе клиента и передаются как `YYYY-MM-DD`.
- Тренировка сериализуется как полный вложенный список упражнений и подходов. Для упражнений с собственным весом UI отправляет `weightKg: 0`.
- Поиск в каталоге дополнительно фильтруется на клиенте при выборе упражнения для тренировки; основной экран каталога отправляет фильтры серверу.
- Диаграммы реализованы локальными React/SVG/CSS-компонентами, сторонняя библиотека графиков не используется.
- В `App.tsx` UI, навигация и разные экраны тесно связаны. Не предполагай наличие компонентной архитектуры по папкам `pages/` или `features/`: таких слоёв сейчас нет.

## Рекомендации для продолжения разработки

- Перед добавлением нового запроса обновляй типы в `src/api.ts` и проверяй фактический ответ соответствующего маршрута.
- При добавлении экрана проверь выбор заголовка и активной навигации в `AppShell`, разбор пути и поведение прямого перехода по URL.
- Не сохраняй секреты в клиенте. `localStorage` доступен JavaScript-коду страницы; любые проверки прав должны выполняться API.
- При изменении расчётов статистики ориентируйся на серверные запросы и [правила хранения и статистики](database.md), а не только на отображаемые подписи графиков.
